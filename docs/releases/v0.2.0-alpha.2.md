# AgentMesh v0.2.0-alpha.2

Release date: 2026-09-29 · Pre-release

This hotfix restores browser task execution on the public HTTP demo. Browsers expose
`crypto.randomUUID()` only on secure origins, so the Alpha.1 Console could create a task but
failed before sending the Run request when opened at an HTTP IP address. The Console and Music
Studio now use `crypto.getRandomValues()` to generate a UUID when needed. Browser asset URLs were
also updated so a refresh loads the fix.

The server task API and workers were unaffected. No data migration or feature-gate change is
required. Existing tasks in `CREATED` state can be started after updating and refreshing the page.

The public demo remains a **deterministic workflow demo**: its default employee returns a traceable
placeholder, not a model-generated summary. To produce substantive answers, configure and assign
a real model-backed employee over HTTPS or the
[SSH-only administration path](../operations/model-connections-ssh.md). Do not enter model keys
on a public HTTP page.

All other features and limitations remain as documented in
[v0.2.0-alpha.1](v0.2.0-alpha.1.md). This is still for evaluation and non-critical single-team
deployments, not production HA or multi-tenant use.

Source changes: [compare with Alpha.1](https://github.com/0YHR0/AgentMesh/compare/v0.2.0-alpha.1...v0.2.0-alpha.2).
